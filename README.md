# kyoten（拠点）

自分と AI の行動記録を集めて、そこから**相棒（アイボ）**を育てるための道具箱。

Claude Code と Codex の会話ログ、polidog.jp と SNS の投稿、git のコミットを
Markdown に写し、検索できるようにして、そこから「何を作り、何に詰まり、
何を繰り返しているか」を観測する。

アイボは polidog のクローンではなく、**横で見ていたやつ**。人格は設定ファイル
ではなく記録から育つ。いまは記録を集めるところまでが建っていて、アイボ自身は
これから（→ [これから](#これから)）。

下敷きは [kani.show](https://kani.show/)（カニ省の長屋）。
間取りの考え方と、性格を設定ファイルに書かず外付けで育てるという判断は
そこから借りた。

## コードとデータは分ける

| | 置き場 | 公開 |
|---|---|---|
| コード（このリポジトリ） | `~/ghq/github.com/polidog/kyoten` | してよい |
| データ（拠点） | `~/Documents/Obsidian/kyoten` | **絶対に private** |

拠点には会話の原文がそのまま入る。仕事の Slack スレッド、取引先の実名、
メールアドレス、認証まわりの試行錯誤——全部入っている前提で扱うこと。
**この2つを同じリポジトリに混ぜてはいけない。**

`bin/util.ts`、引数まわりは `bin/cli.ts`、拠点を読む層は `bin/read.ts`。

素材は下から上へ流れる。1階（会話・自分・アイボ・投稿・作業）は外から集め、
**2階（事典・プロフィール・週報・推移）は拠点の中しか見ない** —— jsonl も
git も直接は読まず、他の部屋が書いたものを畳み直す。だから走らせる順番は
sessions → me → aibo → posts → work → entities → profile → weekly → trend
→ diary で固定になる（日記は素材が全部そろってから）。

## sessions — 会話の書き写し

```bash
bin/sessions.ts                    # 全部写す
bin/sessions.ts --dry-run          # 書かずに結果だけ見る
bin/sessions.ts --since 2026-08-01 # この日以降だけ
bin/sessions.ts --quiet            # 1行だけ報告する（定時便用）
```

環境変数 `KYOTEN` で拠点の場所を変えられる。既定は `~/Documents/Obsidian/kyoten`。

### 原則

- **依存を増やさない** — Node の標準ライブラリだけ。`npm install` は要らない。
- **決定論的** — 同じ入力なら必ず同じ出力。生成日時など揺れる値は書かない。
- **冪等** — 内容が変わらなければファイルに触れない（mtime も動かさない）。
- **原文ママ** — 発話は加工しない。長大なツール出力の末尾だけ省略し、その旨を明記する。
  原本の jsonl は残るので省略は復元できる。

### 実装で踏んだ落とし穴

あとから同じ落とし穴を踏まないための記録。

1. **`session_id` の先頭8文字は一意ではない**
   `52de10eb` で始まる別セッションが実在した。さらにサブエージェントのログは
   親と同じ `sessionId` を持つ（最大18ファイルが同じ ID）。
   出力ファイル名は**元 jsonl と 1:1** になるよう、元ファイル名を鍵にする。

2. **`read_text()` の universal newlines で冪等性が壊れる**
   会話ログには CR を含むものがある（実測10件）。既定の読み方だと CRLF が LF に
   化けて、書いた本文と読み返した本文が永久に一致しない＝毎回 updated になる。
   読み書き両方で `newline=""` を明示する。

3. **MCP の戻り値は `\uXXXX` エスケープされた JSON**
   そのままでは Obsidian で読めず、全文検索でも日本語が引けない。
   JSON として開けるものは開いて `ensure_ascii=False` で書き直す。

4. **発言の「行数」と「件数」は桁が違う**
   `jq ... | wc -l` は行数を数える。実測で 30,887行 ＝ 888件。
   長文をまとめて投げるので1発言あたり平均25行になる。

5. **FTS5 trigram は3文字未満を索引に入れられない**
   日本語は「拠点」「記憶」「原則」のような2文字以下の語が多い。
   trigram の窓が3文字なので、これらは `MATCH` で1件も引けない。
   2文字以下が混ざったときは素の部分一致（全走査）に落とす。
   実測 24,660かたまり / 26MB で 40ms、実用上は問題ない。

6. **`snippet()` は trigram だと窓が狭すぎる**
   1トークン = 3文字なので上限の64トークンでも66文字ほどにしかならない。
   しかも部分一致に落ちたときは使えず、見た目が揃わない。抜粋は自前で切る。

## me — polidog の発言だけ

```bash
bin/me.ts                    # 全部抜く
bin/me.ts --dry-run
bin/me.ts --since 2026-08-01
bin/me.ts --quiet
```

`会話/`（写し）ではなく **jsonl の原本から直接抜く**。
写しの整形を変えても `自分/` は影響を受けない。

出力は `自分/<YYYY-MM>/<YYYY-MM-DD>.md`。1発言 = 1見出し。

```markdown
## 09:12:03 polidog/kyoten（claude-code）

LV2をすすめてほしい
```

### 本人の発話だけを残す

Claude Code の「ユーザー行」には本人の入力でないものが大量に混ざる。
実測 1,066行のうち、本人が打ったのは約550。**フラグで落とせるものは
フラグで落とし、文面での判定は古いログ用の最後の砦にする。**

| 落とすもの | 見分け方 | 実測 |
|---|---|---|
| サブエージェントの会話 | `isSidechain` | — |
| スキル本文・画像・caveat の注入 | `isMeta` | 230 |
| compact の要約 | `isCompactSummary` | 6 |
| サブエージェント完了通知 | `origin.kind == "task-notification"` | 170 |
| 道具の操作（`/clear` `/compact` `/model`） | `<command-args>` が空 | 102 |
| Codex の内部承認プロンプト | 文面 | 14 |

`<command-args>` に中身があるとき（`/omarchy フォントを日本語に…` など）、
それは本人が打った言葉なので**拾う**。実測66件。見出しにコマンド名を残す。

## aibo — アイボの行動記録

```bash
bin/aibo.ts                    # 全部
bin/aibo.ts --dry-run
bin/aibo.ts --since 2026-08-01
bin/aibo.ts --quiet
```

`me.ts` の鏡像。あちらが polidog の発言だけを抜くなら、こちらは **AI 側が
何をしたか**を日ごとに束ねる。相棒は隣の眼なので、自分が何をしたかを
持っていないとただの鏡になる。

出力は `アイボ/<YYYY-MM>/<YYYY-MM-DD>.md`。

```markdown
# 2026-09-03 のアイボ

## どれだけ動いたか

- 会話 22　発言 432　道具 1,324
- モデル: claude-opus-5 413、claude-fable-5-1 14、codex 4
- 手下: 発言 196　道具 744

## つかった道具

Bash 1,168、Edit 35、CommandExecution 28、AskUserQuestion 25、Write 18、Agent 14

## polidog/kyoten

発言 46　道具 100

### やったこと
- 02:51:19 Bash — リポジトリ構成を確認
- 02:51:25 Bash — README・拠点・FTS5 trigram を確認
- 02:53:10 Write — `bin/sessions.ts`
```

### 発言の原文は写さない

assistant の発言は実測 **3,116 ブロック / 890,227 文字**あるが、**全部
`会話/` に入っている**。ここへ写すと索引に同じ文が二重に載り、検索のたびに
同じものが 2 回出る。

だからこの部屋が持つのは、`会話/` にも `作業/` にも無いものだけ:

| | どこにも無かったもの |
|---|---|
| 数 | 会話・発言・道具・モデルの内訳（`会話/` は1セッション単位、日ごとは無い） |
| 手下 | サブエージェントを何回出して、向こうで道具を何回叩いたか（実測 6,265 回） |
| やったこと | 道具に付いている札 |

原文が要るときは `search.ts` で `会話/` を引く。hook が原文を配らず、必要なら
検索させるのと同じ考え方。

### 札は AI 自身が書いた要約

道具の呼び出しには **95% に札が付いている**（実測 8,041 回のうち
`description` 6,719・パス 867・札なし 455）。平均 27 文字。

```
Bash: Fetch kani.show HTML
Bash: Inspect Obsidian vault size and structure
Bash: リポジトリ構成を確認
```

**生のコマンドは取らない。** `work.ts` はつまずいた回だけを拾うので
コマンドを残しているが、こちらは全呼び出しを並べるので、そのままでは鍵の
入ったコマンドが大量に写りうる。`description` → パス、の順で取る。

1日1プロジェクトあたり 60 回まで（実測でいちばん多い日が 2,007 回あり、
全部並べると読めない）。溢れたぶんは `会話/` にある。

### 言われたこと —— 文面では取れなかった

しつけの記録がいちばん人格に効くはずなので、まず**文面で探して数えた**。
「違う」「そうじゃない」「やめて」「直して」「戻して」…… 645 発言中 51 件
当たったが、中身を見ると**本物は 1〜2 割**だった。

| 語 | 当たった | 中身 |
|---|---:|---|
| 直して | 12 | ほぼ普通の依頼（「ページネーションを修正してほしい」） |
| なんで | 11 | ほぼ普通の質問（「なぜ Feature Model を作っても…」） |
| じゃなくて | 10 | 半分は説明文（「ランタイムで気づくじゃなくて…」） |
| 待って | 4 | **3件が誤爆**（「溜まって」「いまって」に当たった） |
| 違う | 2 | これは本物（「なんか違うんだよなぁ」） |

日本語では **AI への依頼と AI の訂正が同じ動詞で書かれる**。「直して」も
「消して」も「戻して」も、普通の依頼としてそのまま出てくる。
落とし穴（`is_error` は「詰まった」ではない）とまったく同じ形だった。

だから**文面判定は捨てて、機械的に確実な合図だけ**にした。

| | 何 | 実測（8日） |
|---|---|---:|
| 選ばせた | AskUserQuestion に答えが返った | 104 |
| 止められた | Esc で中断された（何を止めたかも残す） | 22 |
| 断られた | 道具の実行を拒否された | 13 |

合計 139 件 / 8日 ≒ **17件/日**。どれも曖昧さがなく、全部「polidog が AI の
進路を変えた瞬間」。

とくに **AskUserQuestion の答えは、いままでどの部屋にも入っていなかった**。
`自分/` が見るのは user 行の text ブロックだが、答えは tool_result で来る。
実測 104 件・中央値 230 文字で、選択肢だけでなく自由記述も入っている ——
方針が決まった瞬間の記録そのもの。

```markdown
### 言われたこと

- 07:27:19 選ばせた

  Your questions have been answered: "次はどれをやる？"="Codex のつまずき".

- 09:12:40 Bash を止められた
- 11:30:02 AskUserQuestion を断られた
```

別部屋にしなかったのは、これが「AI に対して起きたこと」だから。その日の
「やったこと」と同じファイルに並んでいたほうが、あとで読むとき文脈が繋がる。

### 実装で踏んだ落とし穴

1. **Claude Code は1つの応答をブロックごとに別の行で書く**
   同じ `message.id` を持つ行がいくつも並ぶ。そこで重ねて数えると道具
   呼び出しがまとめて消える（実測 8,041 回が 3,016 回に減った）。
   `--resume` の写しを落とす鍵は **行の `uuid`**。

2. **`会話/` の `replies` は「発言の数」ではない**
   あちらは jsonl の行を数えるので思考も道具も入る。こちらが数えるのは
   text ブロックだけで、同じ日について違う数になる。だから frontmatter の
   名前も `speech` と分けてある。

3. **モノレポの奥は別プロジェクトに見える（落とし穴18 と同じ）**
   放っておくと `ptyhard/printgraph-neo/node_modules/.pnpm/gaxios@6.7.1/…`
   まで独立したプロジェクトになった（1日で 21 個）。畳み方は `work.ts` から
   `repos()` / `fold()` を borrow する —— 同じ cwd について違う名前を言う
   部屋を作らないため。借りる側ができたので `work.ts` は `import.meta.main`
   で守った。畳んで 13 個になった。

4. **`<synthetic>` はモデルではない**
   Claude Code が自前で作る応答（中断の通知など）に付く。モデルの内訳に
   混ぜると、使っていないモデルを使ったことになる。

5. **道具の拒否も `is_error` で来る**
   「答え」より先に「拒否」を見ないと、拒否まで落ちる。そして
   AskUserQuestion 自体がバリデーションで落ちた回（`<tool_use_error>`）を
   答えに数えると、決めていないものを決めたことになった（実測2件）。

6. **`### 言われたこと` を索引の節名に登録し忘れると、プロジェクト名になる**
   `アイボ/` は見出しからプロジェクトを拾うので、節を足したら
   `search.ts` の `AIBO_SECTIONS` にも足す。

## posts — 外に出した言葉

```bash
bin/posts.ts                    # 全部集める
bin/posts.ts --dry-run
bin/posts.ts --since 2026-08-01
bin/posts.ts --quiet
bin/posts.ts --source bluesky   # ソースを絞る（blog / bluesky / misskey）
bin/posts.ts --site http://127.0.0.1:8000   # 手元の polidog.jp を見る
```

`会話/` と `自分/` が「閉じた場所での言葉」なのに対して、こちらは
**公開された言葉**。polidog.jp の記事と、Bluesky・Misskey の投稿を集める。

記事は 1 本 1 ファイル、SNS は日ごとに束ねる。長さが 2 桁違うので、
1 投稿 1 ファイルにすると数千の断片ができて検索で引いても前後が見えない。

### polidog.jp から取る口を足した

**polidog.jp はもう Hugo ではない。** `polidog/website`（Hugo）は旧サイトで、
現行は `polidog/web` —— Relayer 製の自前 CMS（PHP / FrankenPHP / fly.io、
記事は SQLite）。ローカルの Hugo ソースは公開中の記事と一致しないので使えない。

RSS（`/index.xml`）は最新 20 件しか返さず、20 年ぶんを機械で読む手段が無かった
ので、web 側に JSON の口を足した（[polidog/web#5](https://github.com/polidog/web/pull/5)）。
**HTML と同じ URL** に `Accept: application/json` を付けたときだけ JSON になる。

```bash
curl -H 'Accept: application/json' https://polidog.jp/archives/            # 全記事の索引
curl -H 'Accept: application/json' https://polidog.jp/2026/09/01/git-dmb/  # 記事 1 本
```

索引は本文を持たない（1,300 件ぶんの Markdown は数 MB になる）。記事ごとの
`updatedAt` を版として、書き出したファイルの frontmatter と突き合わせ、
**変わった記事だけ**本文を取りに行く。状態ファイルは要らない。

### SNS は認証なしで全履歴が取れる

| | 口 | 遡り方 |
|---|---|---|
| Bluesky | `public.api.bsky.app` の `getAuthorFeed` | `cursor` |
| Misskey | `misskey.io/api/users/notes` | `untilId` |

どちらもトークン不要。リポスト・リノート（他人の言葉）は落とし、返信と引用は
自分の言葉なので拾って印を付ける。

### 実装で踏んだ落とし穴

7. **いいね数・リアクション数を書いてはいけない**
   過去の投稿でも増減するので、書くと毎回すべてのファイルが書き換わって
   冪等が壊れる。書くのは本文・時刻・ID だけ。

8. **Bluesky の本文は URL が省略表示になっている**
   `record.text` には `github.com/polidog/omar...` という**表示用の文字列**が
   入っていて、そのままでは辿れない。実 URL は `facets`（リッチテキスト注釈）と
   `embed` に別で入っている。本文は原文ママのまま、URL は後ろに `→` で添える。
   実測 100 件中 27 件が該当。Misskey は生の URL がそのまま入るので不要。

9. **日本語スラッグの URL は quote しないと urllib が落ちる**
   `/2012/03/19/父親` のような記事が 248 本ある。そのまま渡すと
   `UnicodeEncodeError`（`Unreachable` ではないので握りつぶされずクラッシュする）。
   セグメントごとに `quote(..., safe="/")` を通す。

10. **「取れなかった」と「0 件だった」を混同しない**
    落ちている日に空のファイルを書くと過去を消す。取りに行けなかったソースは
    ファイルに一切触れずに諦める（`Unreachable`）。ただし**記事は 1 本ずつ独立**
    しているので、1 本落ちても残りは書く —— 全体を捨てるのは、SNS のように
    ページングの途中で欠けると日次ファイルが不完全になるときだけ。

11. **Cloudflare は `Accept` をキャッシュキーに入れない**
    `Vary: Accept` も見ない（効くのは `Accept-Encoding` と Enterprise の
    Custom Cache Key だけ）。同じ URL で HTML と JSON を出し分けるには、
    JSON 側を `Cache-Control: no-store` にしたうえで、Cloudflare に
    「`Accept` が `application/json` を含むなら Bypass cache」の Cache Rule が
    要る。無いと、エッジにある HTML が JSON 要求にも HIT する。

    ルールは既存の「Eligible for cache」より**下**に置く。Cache Rules は
    最初に一致したところで止まらず、[最後に一致したルールが勝つ](https://developers.cloudflare.com/cache/how-to/cache-rules/order/)。
    上に置くと下のルールに上書きされて効かない（一度これで嵌まった）。

12. **`cf-cache-status: BYPASS` は Cache Rule が効いている証拠にならない**
    アプリが `no-store` を返しただけでも `BYPASS` と表示される。キャッシュに
    無い URL は必ずオリジンに届くので、そこだけ見ると「効いている」ように
    見えてしまう。確かめるなら、記事 URL を HTML で 2 回叩いて `HIT` にしてから
    同じ URL に `Accept: application/json` を送る。`HIT` + HTML が返るなら
    効いていない。

13. **索引に載っているのに取れない記事があった**
    記事 URL は 1 種類ではない。`/YYYY/MM/DD/slug`（Hugo 時代・1,294本）と
    `/blog/YYYY/MM/slug`（新しく書いたもの・12本）が同居していて、
    `/2006/10/16` のようにスラッグの無いものまである。URL の形で判定すると
    必ず取りこぼすので、索引と同じ条件で引けるかどうかだけを見る
    （[polidog/web#6](https://github.com/polidog/web/pull/6)）。

## work — 作ったもの・詰まったこと

```bash
bin/work.ts                    # 全部
bin/work.ts --dry-run
bin/work.ts --since 2026-08-01
bin/work.ts --quiet
```

素材は2つ。**git** —— `~/ghq` 配下 66 リポジトリから自分のコミット
（7,820件 / 857日 / 2018-11-16 〜）。何を作ったかはコミットが一番正確で、
しかも全部自分が書いた文章なので嘘がない。**会話ログ** —— 失敗した道具
呼び出し（Claude Code と Codex の両方）。コミットに残らない試行錯誤のうち、
機械が確実に拾えるのはここだけ。

落ちた合図の取り方は2つで違う。Claude Code は `is_error` という真偽値だけ、
Codex は `status: "failed"` と `exit_code` を明示する（後者のほうが確実）。
本文は Claude Code が tool_result のテキスト、Codex は stderr —— 空のことが
多いので `aggregated_output` に落ちる。頭に `Exit code N` を付けて形を揃える。
実測 119 件のうち Claude Code が 92、Codex が 27。

出力は `作業/<YYYY-MM>/<YYYY-MM-DD>.md`。プロジェクトごとに
「つくった / さわった / つまずいた」に分ける。

```markdown
## polidog/kyoten

### つくった
- `862359b` 投稿を集める

### さわった
- `bin/posts.ts`（新規）

### つまずいた
- 11:50:56 WebFetch `https://developers.cloudflare.com/cache/how-to/cache-rules/`
  timeout of 60000ms exceeded
```

### つまずきをどう選ぶか

`is_error` は落ちた合図でしかない。`ls … && wc -l …` のように繋げた
コマンドは、前半が正常に出力を返していても最後の1つがこければ is_error に
なる。全部書き写すと、作業が端末のログになって読み返せなくなる。

3つで絞っている。**人が「やめておこう」と言った回は落とす**（方針が
変わった記録であって、つまずきではない）。**長い応答は落とす**（400字を
超えるものは、たいてい正常な出力に非ゼロが付いただけ）。**しくじりを
名乗る言葉**（`error` `failed` `timeout` `Traceback` `<tool_use_error>` …）
を含むものだけ残す。

実測で 3日ぶん 117件 → 41件。残ったのは WebFetch のタイムアウト、SQLite の
UNIQUE 制約違反、Python の SyntaxError、`fatal: not a git repository`、
`ERROR 2002 … Can't connect to server` といった、読み返す価値のあるものだけ。

**この絞り込みは Codex にも同じものを通す。** `exit_code` が非ゼロでも中身が
普通の出力、という現象は Codex でも同じように起きる（`a | b` の後半だけ
こけた回など）。落ちた合図の確かさと、詰まったかどうかは別の話。

### 実装で踏んだ落とし穴

18. **モノレポの奥で作業した日は、別のプロジェクトに見える**

19. **擬似プロジェクトの名前で全文検索してはいけない**

20. **コミット件名は "Merge pull request #12 from …" が上位を独占する**
    GitHub が書いた定型文なので、どのリポジトリでも同じ語が並んで区別に

## profile — プロフィール・スキル・年表（2階）

```bash
bin/profile.ts                   # 全部
bin/profile.ts --dry-run
bin/profile.ts --quiet
```

事典が「プロジェクトごとの横串」なら、こちらは「技ごと」と「年ごと」と
「いま」。事典と同じく**拠点の中しか見ない**。

```
プロフィール/プロフィール.md          いまの自分（1枚）
プロフィール/スキル/<name>.md   技ごと（71枚）
プロフィール/年表/<YYYY>.md   年ごと（23枚・2004 〜 2026）
```

スキルは**記事タグとコミットの両面**から立てる。この2つは見ている景色が
違う —— 記事タグは「書こうと思ったこと」の20年ぶんの蓄積で、コミットの
拡張子は「実際に手が動いたもの」。並べると差が出る。

```markdown
# php
2006-11-22 〜 2026-09-03（21年）

## 書いた
記事 317 本　2006-11-22 〜 2026-08-26

## 手が動いた
ファイル 3,620　2022-01-04 〜 2026-09-03
- `.php` 3,620
```

`typescript` は記事 13本に対してファイル 9,161、`php` は記事 317本に対して
ファイル 3,620。**書いてきたことと、いま書いているものはずれている。**

プロフィール1枚には「記録の量」（各部屋の大きさ）、「いま手が動いているもの」、
「長くいっしょにいるもの」、20年ぶんの「あゆみ」が並ぶ。

### いつの「いま」か

「直近90日」は**走らせた日から数えない**。拠点にある最後の日から遡る。
今日を基準にすると、素材が1バイトも変わっていないのに日をまたぐだけで
中身が動いて、冪等が壊れる。

### 実装で踏んだ落とし穴

21. **git worktree を二重に数えていた**
    `git worktree add` で作った作業場所は本体と同じ履歴を持つ。両方を
    走査すると同じコミットを2回数える。実測で 8,320 件のうち **524 件が
    二重**だった —— worktree を1つ片付けただけで数字が動いたので気づいた。
    本体の `.git` はディレクトリ、worktree の `.git` はファイルなので、
    そこで見分ける。

22. **「いま」の欄に全期間の合計を出してしまう**
    直近90日で絞ったのは技の一覧だけで、隣に並べた数はどれも全期間の
    合計だった（`php 3,620` は21年ぶん）。月ごとの内訳を持たせて、窓の中
    だけを数える。

23. **タグの付いていない時代がある**
    2004〜2005 の記事にはタグが無い。技の初出だけを見て「はじめて」を
    決めると、その2年が丸ごと落ちる（2004-12-26 が 2006-11-14 になった）。
    期間は記事と作業の日付そのものから取る。

## weekly — 週報（週ごとの観測）

```bash
bin/weekly.ts                   # 全部
bin/weekly.ts --dry-run
bin/weekly.ts --quiet
```

週に1度、拠点を読んでまとめる。数の羅列はプロフィールと年表にあるので、
こちらは**その週に何が起きて、先週と何が違ったか**。
`週報/<ISO年>-W<週>.md`（月曜はじまり・776週ぶん・2004-W52 〜）。

```markdown
# 2026-W36 の週報

## 今週
- コミット 103（先週 127 / -24）　手を動かした日 4
- 会話 247（先週 73 / +174）　発言 344

## よくいた場所
- polidog/omasushi 18
- polidog/kyoten 6（はじめて）

## つまずき
56 件（先週 34 / +22）
Bash 28、mcp__claude-in-chrome__computer 13、Edit 7

## 止まっているもの
- polidog/tehilim 105日（34 コミット積んで）
- polidog/usePHP 92日（63 コミット積んで）
```

「はじめて」「N日ぶり」「止まっている」は、プロジェクトごとの最後の日を
週の並び順に育てながら判定する。

### その週の目でだけ書く

**未来を知らない週報は、二度と変わらない。**「343日止まっている」を
今日から数えると、過去の週報が毎晩書き換わって、読み返したときに
「あのとき何と言われたか」が残らない。だから週を古い順に見て、その週の
終わりまでに分かっていたことだけで書く。実測 776週すべてが `same` のまま
動かない。

いちばん遠くまで見えた例は **2626日ぶり**（7年）に、名前も忘れていた
リポジトリへ戻った週。

### 配達しない

`週報/` に置くだけで、Discord にも通知にも出さない。原則4に並んでいる
「過去に3回止まった仕組み」（`00_思考`・Discord秘書・agent-tracer）は
どれも**外に出す口**を持っていた。まず拠点の中で完結させて、読む習慣が
ついてから考える。

## trend — プロフィールの推移（週ごと）

週報が「その週に何が起きたか」なら、推移は**ここまでで何が積み上がったか**。

プロフィールは「いまの自分」を1枚しか持っていない。先週の自分は上書きされて
消える。週ごとに置いておけば、あとから「2026年9月の自分」を読める。

```
プロフィール/推移/2026-W36.md

  ## つもったもの
  - 会話 335本（+262）
  - はつげん 609（+358）
  - コミット 7,804（+111）
  - さわったリポジトリ 59（+4）
  - 記事 1,307（+2）
  - SNS 1,117日ぶん（+8）
  - つまずき 119（+85）

  ## まだ書いていないもの
  - cafegroup/game7-web-portal 100 コミットをこえた
  - polidog/kyoten はじめて手が動いた（9 コミット）
```

### 節は2つしか作らない

設計図では「何に時間を使い、何が増え、何が止まったか」を書くことになって
いたが、**それは週報がすでに全部書いている**。同じことを別の部屋でもう一度
言うと、どちらも読まれなくなる。

だから残したのは、週報に無い2つだけ。**つもったもの**（プロフィールの差分）と、
**まだ書いていないもの**（ブログのネタ）。

後者は記録ではなく**提案**なので、本当はアイボの仕事。移し先ができるまで
ここに置いてある。

### 素材の読み方は週報から借りる

`scan()`（日ごとに拾う）と `fold()`（週に畳む）は `weekly.ts` から export して
共有している。読み方が2つに割れると、**同じ週について違う数を言う部屋**が
できる。`weekly.ts` は `import.meta.main` で守ってあるので、import しても
走らない。

### 累計は「拠点にあるもの」の累計

**実際に起きたことの累計ではない。** 会話は 30日で消えたぶんが
手元に無いので、写しを取り始める前の週は 0 のまま積み上がらない。上の例で
`会話 335本（+262）` と1週で 262 も増えているのはそのため
（保全を始めた週に、残っていたぶんが一気に入った）。

記事とコミットは最初から全部あるので、こちらは素直に読める。

### ブログのネタの拾い方

`polidog.jp` の記事本文にリポジトリ名が出ていなければ「まだ書いていない」。
ただし**毎週ぜんぶ並べると、書いていないものが延々と並ぶだけ**になるので、
言うのは節目の週だけにした。

- その週に**はじめて手が動いた**
- 累計コミットが **10 / 50 / 100 / 500 / 1000 / 5000 を跨いだ**

照らすのは `<user>/<repo>` の `<repo>` だけで、4文字未満は落とす（落とし穴18 と
同じ話 —— `polidog/web` の `web` を記事本文と突き合わせても意味がない）。
落ちたものはネタに挙がらない。**黙るほうに倒してある** —— 嘘のネタを積む
より、拾い漏らすほうがましなので。

SNS は見ない。「作った」と一度つぶやいただけで書いたことにはしない。

### その週の目でだけ書く

週報と同じ（落とし穴22）。累計もネタも、その週の終わりまでしか知らない。
「まだ書いていない」かどうかも、その週の終わりまでに出た記事だけで決める。
未来を知らない推移は二度と変わらないので、776週ぶんが完全に冪等になる。

```bash
bin/trend.ts              # 全部
bin/trend.ts --dry-run
bin/trend.ts --quiet
```

## diary — アイボが書く1日のまとめ

```bash
bin/diary.ts                    # 書けるところまで
bin/diary.ts --dry-run          # 渡すものを見るだけ（API を叩かない）
bin/diary.ts --since 2026-09-01
bin/diary.ts --quiet
```

ここまでの部屋は全部「機械が数えたもの」だった。ここが最初の、**アイボ自身が
書く部屋**。その日の `アイボ/` `自分/` `作業/` `投稿/` と、きのうの日記を渡して、
400〜800 字の散文を1枚もらう。

### この部屋だけ原則が違う

書き手が LLM なので、決定論も冪等も成り立たない。代わりに置いたのは:

> **追記のみ・一度書いたら直さない。**

日付ごとに1枚積んで、できたものには二度と触らない。落とし穴（「N日ぶり」を
今日から数えない）で守りたかったこと —— 過去が毎晩書き換わって「あのとき何と
言われたか」が残らなくなる —— は、これで同じように守れる。
書き直したいときは**そのファイルを手で消す**。道具に上書きの口は作っていない。

同じ理由で、この部屋だけ「走らせた日」を見てよい（きのうまでを書く）。冪等が
壊れる心配が無いので、時計を禁じる理由がなくなる。逆に「素材のいちばん新しい
日をまだ開いているとみなす」やり方にすると、定時便が 03:00 に走るたびに
きのうが開いたままになって、日記が常に1日遅れる。

### 人格をプロンプトに書かない

渡しているのは**立ち位置と決まりごと**だけ。口調も性格も書いていない。

```
あなたはアイボ。polidog の作業を横で見ていた相棒として、その日の日記を書く。

- polidog のクローンではない。隣で見ていた側として書く。
- 素材にあるのは、全部あなたが立ち会ったこと。断言してよい。
- 素材に無いことは書かない。推測で埋めない。
- polidog は二人称で呼ぶ。
…
- 最後に、言いたいことを一つだけ書く。素材から言えることに限る。
```

何を言うかは、その日の拠点が決める。記録が増えれば言うことが変わる ——
それが育っている証拠になる（kani.show から借りた判断）。

### 書くのは「立ち会った日」だけ

素材は `アイボ/` があることが前提。だから日記は**アイボの誕生日 2026-08-28
から**始まる。`作業/` は 857 日ぶんあるが、それは後から読んだ記録であって、
立ち会ってはいない。「見た」と「読んだ」の線がそのまま部屋の範囲になる。

### 実装で踏んだ落とし穴

1. **`claude -p` はセッションのログを残す**
   そのままだと**日記を書いたこと自体がその日の会話ログになり**、`会話/` と
   `アイボ/` に混ざって循環する（実測: 1回呼ぶと jsonl が1本増えた）。
   `--no-session-persistence` が要る（`--print` のときだけ効く）。
   hook も `--settings '{"hooks":{}}'` で黙らせる。

2. **mise の shim は起動通知を stdout に出す**
   `mise ~/.config/mise/config.toml tools: claude@2.1.259` が**日記の1行目に
   なった**。`MISE_QUIET=1` を渡す。別プロセスの出力を本文にするときは、
   まず「余計なものを stdout に出さないか」を見る。

3. **見出しの無い文書は `readDoc()` が本文を落とす**
   `lead` は最初の1行しか持たず、残りは `sections` にも入らない。日記は
   段落しかないので、ブラウザにも端末にも1行しか出なかった。`Doc.body` を
   足して、見出しが無いときはそれを描くようにした。

4. **`CLAUDE.md` を拾わせない**
   呼び出しの cwd を一時ディレクトリにしてある。リポジトリの中で呼ぶと
   プロジェクトの指示が混ざって、渡した素材以外のものを見て書く。

## /aibo — アイボに聞く

```
/aibo                      きょうのことを言う
/aibo あの Cloudflare の話  拠点を引いて答える
```

`commands/aibo.md` を `~/.claude/commands/aibo.md` から symlink する。
どのリポジトリでも呼べる。外すときは symlink を消すだけ。

```bash
mkdir -p ~/.claude/commands
ln -sfn ~/ghq/github.com/polidog/kyoten/commands/aibo.md ~/.claude/commands/aibo.md
```

引数が無ければ、その日の `アイボ/` と `作業/` といちばん新しい日記を読んで
**2〜4行**言う。まとめではなく、気づいたことを1つか2つ。引数があれば、
まず `search.ts` で拠点を引いてから答える。**引けなかったら「拠点には無い」**
と言う —— 無いことも観測結果なので、憶測で埋めない。

### 立ち位置は1枚しか置かない

`commands/stance.md` に、**誰で、何を断言してよくて、何を言わないか**だけを
書いてある。`/aibo` と `diary.ts` は両方これを読む —— 相棒が2人に割れると、
喋る側と書く側で別の記憶を持つことになる。

```markdown
- **クローンではない。** polidog として喋らない。隣で見ていた側として喋る。
- **「見た」と「読んだ」を分ける。**
  - `会話/` `自分/` `アイボ/` `日記/` は 2026-08-28 から。断言してよい。
  - `投稿/`（2004 〜）と `作業/`（2018 〜）は後から読んだもの。伝聞として言う。
- **拠点に無いことは言わない。** 引けなかったら「拠点には無い」と言う。
…
口調も性格もここには書かない。何をどう言うかは、その日の拠点が決める。
```

最後の一行が肝で、**口調を書いていない**。この1枚を経由させるようにしたら、
日記が「読んだ範囲で言うと」と自分で断りを入れるようになった。人格を
書き足したのではなく、立ち位置を1か所にしただけでそうなっている。

### 拠点には書かない

`/aibo` は読むだけ（原則5: 書き込み口を絞る）。そして**よそのリポジトリの
原文は貼らない** —— 仕事のリポジトリでも呼べてしまうので、ほかの場所の話に
触れるときは名前と数までにとどめる（hook と同じ線）。

  `~/Documents/Obsidian/reading-notes/`（`KYOTEN_READING` で変えられる）
- 見出し単位で切り、パス・日付・プロジェクト・行番号を持つ

## web — ブラウザで見るまとめ

```bash
bin/web.ts                # 立ち上げてブラウザを開く
bin/web.ts --port 9999
bin/web.ts --no-open
```

Obsidian で拠点を開くと、見えるのは日付順に並んだテキストになる。ここは
23年ぶんを**1枚のまとめ**にして返す。上から下へ読むもので、一覧も検索も
持たない —— 776週の週報や71枚のスキルを潜って読むのは端末の仕事。

出るのは、プロフィール（記録の量・スキル・週報の数）、**今週の週報**、
スキルの上から12枚、いま手が動いているものと長くいっしょにいるもの、
23年のあゆみ、最近いた場所の8つ。週報だけは節を原文のまま出す ——
向こうから来た問いは要約しない。

- 口は `/api/summary` の1本だけ。画面は `bin/web.html` 1枚（CSS も JS も
  中にある）。リクエストのたびに読み直すので、立ち上げたまま直せる
- **127.0.0.1 に固定**。`--host` は用意していない —— 拠点には取引先の実名も
  Slack のスレッド全文も入っている。外向きに開ける口を最初から作らない
- 拠点には**一切書かない**。素材は `bin/read.ts` から取る

見た目は[設計図](https://claude.ai/code/artifact/08ea4f4f-4ebf-4764-a404-69a1fb8ed669)に
合わせてある。明るい地に白いカード、2px の線と `0 2px 0` の段差、見出しは
DotGothic16。黒い枠は**全面に広げず、要所のアクセント**にだけ使う
（プロフィールの数字のところ）。CSP は外を向くのを字の形だけに絞って
あり、拠点の中身が外へ出る口はない。

### 拠点の中身は必ずエスケープして描く

会話原文には HTML も `<script>` も普通に入っている（人のコードの話をして
いるのだから当たり前）。描くのは箇条書きと段落だけに絞って、中身は全部
エスケープを通す。`**強調**` と `` `code` `` だけ拾う。

### 実装で踏んだ落とし穴

1. **`listen()` は非同期。** ほかの道具と同じ `process.exit(main())` の形で
   書くと、建った端から閉じる。対話するものは戻り値で終わらせない。

## browse — 端末で歩く

```bash
bin/browse.ts                    # 開く
bin/browse.ts スキル php          # その部屋・その行き先から始める
bin/browse.ts --plain 週報      # 対話せず1回だけ描く（パイプ用）
bin/browse.ts --plain さがす 冪等
```

`↑↓` でえらんで、`→` で入って、`←` で戻る。ブラウザ（`web.ts`）と同じ
ものを見るが、こちらは潜って原文まで読める。中身は `bin/read.ts` を共有
していて、こちらも拠点には書かない。

端末の幅は自前で数える。`.length` は UTF-16 の単位なので、日本語を並べると
枠が崩れる（落とし穴24 と同じ話）。East Asian Width の表を丸ごと持つと重いので、
拠点に出てくる範囲だけを幅2として数える。

### 実装で踏んだ落とし穴

1. **端末は複数のキーを1回の `data` で渡してくる。** 速く打つと
   `↓↓q` が1つの塊で届く。塊のまま比べるとどのキーにも当たらず、**全部
   無視される**。キーに割ってから1つずつ流す。
2. **描くのを最後の1回にまとめると、キーの処理が古い画面を見る。** 塊で
   届いた `Enter` が、前の画面のカーソル行を開いた（検索の結果を開いた
   つもりで、プロフィール画面の1行目にあった `typescript` が開いた）。
   キーごとに、いま居る場所のページを引き直す。
3. **打っている間は検索しない。** 1打ごとに 44,000 かたまりを舐めることに
   なる。`Enter` で確定してから引く。

## nightly — 定時便

夜のうちに拾って回る。sessions・me・aibo・posts・work・entities・profile・
weekly・trend・diary を順に流し、索引を刻み直して、拠点を git commit する。
**diary だけは中で `claude` を呼ぶ** —— きのうの日記を1枚書く。

```bash
bin/nightly.ts              # 全部流す
bin/nightly.ts --dry-run    # 書かずに、コミットもせずに流す
bin/nightly.ts --no-commit  # 集めるけどコミットはしない
```

**1つが失敗しても次へ進む。** 投稿が取りに行けない夜でも、手元の
ログからの写しは進められる。全部やってから、失敗があれば非ゼロで終わる。

**変化が無ければコミットしない。** 何も起きなかった日に空のコミットを
積まない。

### systemd に載せる

```bash
ln -sf ~/ghq/github.com/polidog/kyoten/systemd/kyoten.service ~/.config/systemd/user/
ln -sf ~/ghq/github.com/polidog/kyoten/systemd/kyoten.timer   ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now kyoten.timer
```

symlink なので、`systemd/` を直せば `daemon-reload` だけで反映される。
リポジトリを別の場所に置いているなら `ExecStart=` のパスを直す。

```bash
systemctl --user list-timers kyoten.timer   # 次にいつ起きるか
systemctl --user start kyoten.service       # いま1回流す
systemctl --user status kyoten.service      # しくじっていないか
journalctl --user -u kyoten.service -o cat  # 何を言ったか
```

毎晩 03:00。`Persistent=true` にしてあるので、その時刻にラップトップが
閉じていても次に起きたときに取り戻す（`Persistent=` は `OnCalendar=` の
タイマーにしか効かない）。

**しくじった夜は failed のまま残す。** 消えると、取れていないことに
気づけない。拠点は壊れない（取りに行けなかったソースはファイルに触れずに
諦める）ので、次の便で直る。

**journald に拠点の中身を出さない。** 道具はどれも `--quiet` の1行だけを
返す。件数以上のものを出すと、会話の原文がシステムログに漏れる。

### 実装で踏んだ落とし穴

14. **検索の報告は stdout ではなく stderr に出る**
    `search.ts 語 | grep …` としたときに刻み直しの行が混ざらないよう、
    検索結果だけを stdout に流している。定時便が「何も言わずに終わった」と
    言い出したらこれ。名前で分岐せず、stdout が空なら stderr、の順で拾う。

15. **user service の PATH は最小**
    道具どうしの呼び出しは `process.execPath` を使うので困らないが、
    **拠点のコミットで `git` を呼ぶ**ので `/usr/bin` が要る。
    `Environment=PATH=` で明示する。

16. **`git status --porcelain` は未追跡ディレクトリを1行にまとめる**
    そのまま数えると「投稿 1」という嘘のコミットになる。
    `--untracked-files=all` でファイル単位まで開かせる。

17. **`.obsidian/workspace.json` は Obsidian を開くたびに変わる**
    追跡すると、定時便が毎晩それだけをコミットする。拠点の `.gitignore` で
    外した（設定の3ファイルは残す —— 拠点を別の場所へ移したときに要る）。

18. **git は ASCII でないパスを8進エスケープして返す**
    部屋の名前を日本語にした回、`プロフィール/` で始まるかを見ても1件も
    当たらず、5,358件の変更を「変化なし」と報告した。
    `-c core.quotepath=false` を付ける。

19. **改名は `R  <前> -> <後>` の1行で来る**
    前だけ見ると、部屋ごと名前を変えた回にコミットを飛ばす。
    矢印があれば後ろを取る。

## hook — 会話の合間に鳴るもの

定時便が「溜める」係なら、こちらは「思い出させる」係。

2階まで建てても、こちらから見に行かないと何も返ってこない。それは原則4で
並べた止まった3つ（`00_思考`・Discord秘書・agent-tracer）と同じ形をしている。
**溜めた記憶は、引く動機が無いと使われない。**

Claude Code の hooks から呼ばれる。stdin に来る JSON の `hook_event_name`
で鳴らし分けるので、入口は1本だけ。

| いつ | 何をするか |
|---|---|
| `SessionStart` | 拠点の大きさ・いま居る場所の事典・いちばん新しい週報・検索の呼び方を配る |
| `UserPromptSubmit` | 過去を指す言い回しを見つけたら検索を促す |
| `SessionEnd` | 終わったその場で会話に写す（夜まで待たない） |

```bash
echo '{"hook_event_name":"SessionStart","cwd":"/home/polidog/ghq/github.com/polidog/kyoten"}' | bin/hook.ts
echo '{"hook_event_name":"UserPromptSubmit","prompt":"あの話どこだっけ"}' | bin/hook.ts
bin/hook.ts --check      # `自分/` に当てて、何割で鳴るか数える
```

### 登録する

`~/.claude/settings.json` の `hooks` に足す。プロジェクトごとではなく
ユーザー全体に置く —— kyoten の中でだけ鳴っても意味がない。

```json
{
  "hooks": {
    "SessionStart": [
      { "matcher": "*",
        "hooks": [{ "type": "command", "command": "\"$HOME/ghq/github.com/polidog/kyoten/bin/hook.ts\"", "timeout": 5 }] }
    ],
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "\"$HOME/ghq/github.com/polidog/kyoten/bin/hook.ts\"", "timeout": 5 }] }
    ],
    "SessionEnd": [
      { "hooks": [{ "type": "command", "command": "\"$HOME/ghq/github.com/polidog/kyoten/bin/hook.ts\"", "timeout": 30 }] }
    ]
  }
}
```

外すときはこの3つを消すだけ。hook は拠点に書かないので、消しても何も残らない
（SessionEnd の写しだけは sessions が書くが、それは夜の便が書くものと同じ）。

### 鳴らないほうがましなので、何があっても 0 で終わる

鳴らないのは構わない。hook のせいでセッションが止まるのがいちばん困る。
stdin が壊れていても、索引が無くても、拠点ごと存在しなくても、例外を全部
飲んで黙って 0 で終わる。実測 —— SessionStart 77ms、UserPromptSubmit 54ms、
SessionEnd 115ms。

### 拠点の中身は数と見出しだけ配る

hook は**全プロジェクトのセッション**で鳴る。仕事のリポジトリでも鳴る。
だから配るのは、週報の見出しと数、事典の台帳1行、検索の呼び方まで。
**会話の原文は渡さない**（そこに取引先の実名もメールアドレスも入っている）。
原文が要るときは、呼ばれた側が `search.ts` を叩いて自分で取りに行く。

### 過去参照は実測 1.5% でしか鳴らない

`UserPromptSubmit` の語彙は、`自分/` の 609発言に当てて決めた。

```
だっけ            7
どこにある         1
どうだったっけ      1
                 ── 9 件 / 609 発言 = 1.5%
```

`あの話` `例の` `以前` `前回` `このまえ` `昔` はどれも 0 件だった。7日ぶんしか
無いので「使わない語」と決めつけず、precision の高いものは残して
ある。**入れなかったのは `前に＋動詞`** —— 「この行の前に書いて」のような
指示文と見分けがつかず、鳴りすぎるとすぐ読み飛ばされるようになる。

鳴る回数が少ないのは負けではない。毎プロンプト鳴る hook は、鳴っていないのと
同じになる。

### いま居る場所は cwd から引く

`SessionStart` の payload には `cwd` が入っている。`slugFromCwd()` で
`<user>/<repo>` にして事典を引くと、「このリポジトリについて拠点は何を
憶えているか」が最初の1行で返る。プロンプトの中の固有名詞を探すより、
これは確実で、しかも1セッションに1回しか走らない。

事典の名前で照らし合わせるのは `/` を含むものだけにしてある（落とし穴18 ——
`Work` や `_home` はただの単語なので、名前の一致に意味がない）。

### 実装で踏んだ落とし穴

18. **`.ts` は ESM なので `require` が無い**
    道具は Node が型注釈を剥がして直接実行する。拡張子だけ `.ts` の ESM
    なので、`require("node:sqlite")` は `ReferenceError` になる。遅延読み
    込みのつもりで書くと、鳴った瞬間にだけ落ちる（黙って 0 で終わるので、
    気づくのは「なぜか鳴らない」だけ）。静的 import に揃える。

19. **「何があっても 0 で終わる」は `main` の中だけでは守れない**
    読み込み時に落ちるもの（構文エラー・import の失敗）は try/catch の
    外側にいて、終了コードは 1 になる。`UserPromptSubmit` が非ゼロで
    終わると**そのプロンプト自体が止まる**ので、全セッションが動かなく
    なる。直したら登録する前に必ず1回叩く。

    ```bash
    echo '{"hook_event_name":"UserPromptSubmit","prompt":"あの話だっけ"}' | bin/hook.ts
    echo "終了コード $?"   # 0 でなければ登録しない
    ```

20. **`SessionEnd` の写しは sessions に 1本だけ渡す口が要る**
    `sessions.ts --file <jsonl>` を足した。名前の衝突（落とし穴1）はこの口では
    見ていない —— 全部を写す夜の便が刻み直すので、そちらに任せる。

## 道具の書きかた

```bash
bin/me.ts --quiet    # そのまま実行できる（ビルドしない）
```

**Node 24 以降は `.ts` を直接実行できる**（型注釈を剥がしてから走らせる）。
だからビルド手順もトランスパイラも要らず、依存はゼロのまま型が書ける。
代わりに、**実行時の意味を持つ TypeScript 構文は使えない** ——
`enum`・`namespace`・`constructor(readonly x)`（parameter property）・
decorator は落ちる。型注釈と `interface` と `type` だけで書く。

型検査は走らせていない（`tsc` を入れると依存が増える）。エディタの LSP に
任せ、正しさは**出力の突き合わせ**で担保している —— これらは元々 Python で
書かれていて、1本ずつ移すたびに「同じ拠点に対して1バイトも違わない出力を
出すか」を `diff -r` で確かめた。

### 移すときに踏んだ落とし穴

24. **JS の `.` は `\r` にマッチしない**
    Python の `.` はする。会話ログには CR を含む行があるので（落とし穴2）、
    `^## (.+)$` のままだと `## 見出し\r` を見出しとして拾えず、検索の
    かたまりが 40,308 → 40,194 に減った。行のパターンは `[^\n]` で書く。

25. **`.slice(0, n)` は UTF-16 の単位で切る**
    Python の `text[:n]` はコードポイント。絵文字や Nerd Font の私用領域
    文字が混ざると 1 文字ずれて、内容が同じなのに毎回 updated になる。
    `[...text].slice(0, n).join("")` で数える（`util.ts` の `take()`）。

26. **`execFileSync` は成功したときの stderr を返さない**
    検索は検索結果と混ざらないよう刻み直しの報告を stderr に出すので、
    定時便から呼ぶと「何も言わずに終わった」ことにされた。`spawnSync` を使う。

27. **`Date` はミリ秒しか持たない**
    Python の `datetime.isoformat()` はマイクロ秒6桁を出す。拠点の
    frontmatter に合わせるには 3 桁に `000` を足す（元のログがミリ秒精度
    なので情報は落ちない）。`util.ts` の `isoJst()`。

28. **`JSON.stringify` はキーの順を保つ**
    Python の `json.dumps(sort_keys=True)` は再帰的に並べ替える。順が違うと
    内容が同じでも毎回 updated になるので、自分で並べ替える（`sortedJson()`）。

29. **Python の `str(list)` は内部表記を吐く**
    Codex の command は `["/usr/bin/bash", "-lc", "…"]` という配列で来る
    ことがあり、Python 版はそれを `str()` に通して
    `['/usr/bin/bash', '-lc', "…"]` という Python の repr を拠点に書いていた。
    移すついでに両方とも JSON 表記へ直した。

## ログを消させない

Claude Code は `cleanupPeriodDays` 未設定だと **30日でログを消す**。
`~/.claude/settings.json` に設定済み:

```json
{ "cleanupPeriodDays": 3650 }
```

写しを取る仕組みが動いていても、取りこぼした期間の穴は埋められないので、
原本も残す。

## これから

**アイボの4段階は建て終わった。** ここから先は、育つかどうかを見る番。

アイボは polidog のクローンではなく**相棒**にした。クローンは「これは本当に
自分か」を誰も判定できないが、相棒の言うことは事実なので当たり外れが分かる。
そして「今日は何をしていたか」を要約させるなら、視点が同じクローンより、
横から見ていた側のほうが新しいことを言う。

決めたこと:

- **アイボは1匹。** Claude Code と Codex の記録を両方食べる。道具ごとに
  個体を分けない（記憶には `models:` のタグが付いている）
- **「見た」と「読んだ」を分ける。** `会話/`（2026-08-28 〜）は一緒にいた
  ので断言してよい。`投稿/`（2004 〜）は後から読んだので伝聞として言う。
  アイボの誕生日は 2026-08-28
- **人格を設定ファイルに書かない。** `/aibo` には「拠点を読め、そして喋れ」
  しか書かない。何を言うかは拠点が決める（kani.show から借りた判断）
- **`/aibo` は拠点に書かない。** 仕事のリポジトリで呼ばれるので、書くと
  他所の話が混ざる。書くのは夜の側

やる順:

1. ~~**`アイボ/`（AI の行動記録）**~~ **建てた**（→ [aibo](#aibo--アイボの行動記録)）

### 育っているかを見る

人格を書き足さずに育てる、という賭けなので、確かめかたも決めておく。

- **同じ問いを違う日に投げて、答えが変わるか。** 決定論の掟のちょうど
  裏返し。変わらないなら、記録が効いていないということ
- **日記が「読んだ範囲で言うと」と自分で断るか。** 立ち位置を1枚に
  まとめたら実際にそうなった。「見た」と「読んだ」の線が保てているかの目印
- **`/aibo` が「拠点には無い」と言えるか。** 憶測で埋めはじめたら、
  相棒ではなく作文機になっている
