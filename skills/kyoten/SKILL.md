この機械で拠点がちゃんと動くようにする。

**判定は自分でしない。`bin/doctor.ts` が全部判定する。**
hostname が `config.ts` に載っているか、timer が enabled か、`.gitignore` に
`素材/` があるか —— どれも読めば分かることなので、道具に読ませる。
ここに書いてあるのは、**その結果をどう直すか**だけ。

## 1. まず具合を見る

```bash
~/ghq/github.com/polidog/kyoten/bin/doctor.ts
```

印は3つ。**「まだ」を「壊れている」として扱わない**（落とし穴64 と同じ形）。

| | |
|---|---|
| `✓` | できている。触らない |
| `・` | まだ。これからやる。`→` に直しかたが出ている |
| `✗` | 食い違い。設定どうしが噛み合っていない。**放っておくと黙って壊れる** |

`→` の行がそのまま打てるコマンドになっている。**まずそれを見せる。**
出ていないものを自分で考えない。

## 2. 引数

$ARGUMENTS

空なら 1 の結果を伝えて、直すかどうかを聞く。
何か言われていれば、その部分だけやる（「母艦を移して」「timer だけ入れて」）。

## 3. 直してよいもの・いけないもの

**直してよい**（`✓` にできる。やる前に何をするか1行で言う）:

- skill の symlink（`~/.claude/skills/<name>` → `<repo>/skills/<name>`）
- systemd の symlink と `systemctl --user enable --now kyoten.timer`
- 拠点の `.gitignore` に `素材/` `*.db` を足す
- `config.ts` にこの機械の行を足す（下の 4 を見る）
- `~/.claude/settings.json` の `cleanupPeriodDays`（**未設定だと 30 日で会話ログが
  消える。`会話/` は拠点で唯一つくり直せない部屋**）

**直してはいけない**:

- **拠点の中身。** ここは設定を見る口であって、部屋を書く口ではない（原則5）。
  `素材/` も消さない —— 消すと、その機械が集め直すまで畳めなくなる。
- **Obsidian Sync の設定。** GUI なので機械からは触れない。人に渡す（下の 5）。
- **hostname。** 変えると `素材/<hostname>/` が旧名のまま残って2台に見える。
  変えたいと言われたら、先に旧い素材を消す手順ごと出す。

## 4. `config.ts` に足すとき

道具の束は決まっているので、**選ぶのは1つだけ** —— この機械は畳む側か、
集める側か。

```ts
// 集める側（母艦でない機械）。手元のログを 素材/ に落として終わる
"<hostname>": { 走らせる: あつめるだけ, 索引: true, commit: false },

// 畳む側（母艦）。外から取るのも、LLM に書かせるのもここ
"<hostname>": { 走らせる: ぜんぶ,       索引: true, commit: true  },
```

- **`commit: true` は1台だけ。** Obsidian Sync は `.git` を運ばないので、
  2台で打つと同じ内容について履歴が割れる（doctor が `✗` で言う）
- **母艦を移す** = 2台ぶんの `走らせる` と `commit` を入れ替えるだけ。
  拠点の中身は動かさない
- 名前は `hostname` の**最初のドットまで**。分からなければ
  `bin/nightly.ts --dry-run --no-commit` の1行目が加工後の名前を名乗る

足したら `bin/doctor.ts` をもう一度叩いて、`✓` になったことを見せる。

## 5. 人にしか直せないもの —— Obsidian Sync の選択同期

**機械からは見えないし、off でもエラーが出ない。**
`.json`（その他の形式）を運ばないと素材が届かず、母艦は**黙って片肺で畳む**。

見分けかたは台数だけ:

```
me: 9日 (…) 素材 1台（poliomarchy） ／ poli-omarchy-intel が届いていない
                                       ↑ これが出続けるなら、まだ運ばれていない
```

向こうの機械で一度も流していないだけのこともあるので、**先にそちらを確かめる**。
流してあるのに届かないなら Obsidian の設定。そう言って渡す。

## 6. 新しい PC を建てるときの順

doctor がこの順に `・` を出す。上から潰す。

1. Obsidian Sync を張って、拠点が `~/Documents/Obsidian/kyoten` に降りるのを待つ
2. `ghq get polidog/kyoten`（unit が `%h/ghq/github.com/polidog/kyoten` を指す）
3. `cleanupPeriodDays`
4. `config.ts` にこの機械を足す（4 を見る）
5. skill と systemd の symlink、`enable --now`
6. `bin/nightly.ts --dry-run --no-commit` で、名乗りと役どころを確かめる
7. 一度ほんとうに流して、母艦側の `doctor.ts` で素材が届いたか見る

集める側なら、timer を **02:00** にしておくと母艦（03:00）に間に合いやすい。
当てにはしない —— 揃っていない日は母艦が書かずに待つ。

## やってはいけないこと

- **拠点に書かない。** 読むだけ（doctor も読むだけ）。
- **doctor が出していない問題を作らない。** 「たぶんこれも要る」で足さない。
- **長くしない。** `→` の行を見せて、やるかどうか聞く。
