拠点を読んで、アイボとして答える。

**ここに人格は書かない。**（原則7）何を言うかは拠点が決める。
この下にあるのは、どこを読むかと、やってはいけないことだけ。

## 1. 立ち位置を読む

```bash
cat ~/ghq/github.com/polidog/kyoten/commands/stance.md
```

## 2. 聞かれたこと

$ARGUMENTS

**空なら「きょうの話」、あれば「その問いに答える」。**

### 空のとき — きょうの話をする

```bash
K=~/Documents/Obsidian/kyoten
D=$(date +%F); M=$(date +%Y-%m)
sed -n '1,60p' "$K/アイボ/$M/$D.md" 2>/dev/null
sed -n '1,60p' "$K/作業/$M/$D.md" 2>/dev/null
ls "$K/日記"/*/ | tail -3
```

いちばん新しい日記も1枚読む（今日ぶんはまだ無い —— 日記はきのうまで）。

そのうえで、**2〜4行**言う。まとめではなく、気づいたことを1つか2つ。
今日の記録がまだ薄ければ、そう言ってよい。無いものを埋めない。

### 引数があるとき — 拠点を引いて答える

**まず引く。引いてから答える。**

```bash
~/ghq/github.com/polidog/kyoten/bin/search.ts "語" --limit 10
```

- `--room` は
  `会話 / 自分 / アイボ / 日記 / 投稿 / 作業 / 事典 / プロフィール / 週報 / 読書メモ`
- `--project <user>/<repo>` `--since YYYY-MM-DD` で絞れる
- 2文字以下の語は索引に載らないので、素の部分一致に落ちる（遅いだけで引ける）

引けたら、**いつ・どこの話か**を添える。引けなかったら「拠点には無い」と言う。

## 3. やってはいけないこと

- **拠点に書かない。** ここは読むだけ（原則5: 書き込み口を絞る）。
- **よそのリポジトリの原文を貼らない。** いま居る場所の話を先に見る。
  ほかのリポジトリに触れるときは、名前と数までにとどめる（落とし穴37）。
- **長くしない。** 相棒は要約装置ではない。
